# 超分 / 降噪：本轮结论与后续形态

> 状态：**未实现**。本文件只记录评估结论，不代表任何已实现或已验证的能力。
> 评估日期：2026-11-05。评估依据为只读阅读参考项目 `Final2x`（本地副本）与 npm 元数据，未运行任何模型。

## 1. 为什么不复用 Final2x

参考项目 `EutropicAI/Final2x`（BSD 3-Clause，Copyright (c) 2023 Tohrusky）不能直接为我们所用：

- 它是 **Electron 前端 + Python 核心**的结构，前端只是壳，真正的推理在 Python 侧。
- Python 核心依赖 `cccv==0.1.0`（基于 **NCNN** 的模型库），另外还有 `torch~=2.7.1`、`torchvision`、`opencv-python`。
- 模型**不由项目自带**：运行时从 `https://github.com/EutropicAI/cccv/releases/download/model_zoo/` 下载到缓存目录（`CCCV_CACHE_MODEL_DIR`），缓存目录在 `core/tests/integration/test_frozen_tls.py` 里可以看到。

结论：它是一套本地可执行程序 + 原生推理栈，**我们的编辑器是纯前端页面，没有 Python 运行时，也无法嵌入 NCNN 原生库**。它的代码结构可以借鉴，能力不可复用。

## 2. 浏览器路线的真实条件

技术上存在浏览器内离线超分的路线，但不满足“直接可用”：

- 运行时需要换成 `onnxruntime-web`（npm `1.31.1`，**MIT**），可选 WASM 或 WebGPU 后端。
- **模型许可是独立问题**：开源超分项目常见做法是代码一个许可、权重另一个许可，且相当一部分权重带非商用条款。**在逐个核实之前，我们不能宣称任何模型可以随包分发或商用**。代码是 BSD/MIT 不代表权重能用。
- 体积与内存：模型是 MB 级资产，即使按需加载也仍是数 MB 到数十 MB 的下载；1200px 图放大 2× 后为 2400×2400，单张 RGBA float 张量接近百 MB，必须分块（tiling）处理。
- WebGPU 在我们所在的 WebView 里是否可用，**尚未验证**；只有 WASM 时速度会明显更慢。

**耗时没有任何实测数据**，本文不提供具体秒数作为承诺。若后续要做，必须先 POC 实测单图耗时与内存峰值，再谈是否上线。

## 3. 如果要做，形态是什么

- 入口形态：**用户自带模型**。用户在本地选择 `.onnx` 文件，页面加载后在本机推理；项目**不随包分发任何权重**，从根上避开“模型能否再分发”的问题。
- 加载方式：`onnxruntime-web` 与模型都走**按需 chunk / 用户文件**，主包体积不变。
- 前置条件：需要单独立项，完成 ①单图耗时与内存实测 ②WebGPU 可用性探测 ③失败与不支持时的中文提示 ④与引擎历史/撤销一致的处理（超分结果必须作为一次原生图层动作进入历史，不能绕过 revision）。
- 在此之前，界面上不提供该入口，也不对外宣称支持超分。

## 4. 结论

- 本轮**不做**超分/降噪，不引入依赖，不进主包。
- 不做不等于否认可行性：路线存在，但模型许可、体积、性能三项都还没有证据，不能写成“已支持”。
- 后续若立项，按第 3 节的“用户自带模型 + 按需 chunk”形态评估。
