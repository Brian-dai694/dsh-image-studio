# dsh-image-studio 开发计划

最后更新：2026-11-09（对应 0.21.0）
基线：`origin/main` 与本地一致；插件测试 **261/261**，原生桥接测试 **34/34**。

## 目标

让这个 DSH 图片插件能**自主完成套版图**：自主抠图 → 找素材 → 套模板 → 排文字 → 批量出成品，
全程有人可核对的中间态，不把 mock 当生产能力。

## 进行中 / 下一步（按优先级）

### P0-2 确认卡片可核对（未完成）
- 现状：确认框展示原始 `payload` JSON，人看不出「这个 layerId 是哪一层」。
- 要做：解析成图层名 + 坐标 + 尺寸后再展示；套版/重绘的确认框都改。
- 验收：确认框文本里出现真实图层名；测试断言解析字段。
- 参考：LayerShop `policy.js` 的「策略作用在规范化调用上」。

### P1-1 送后端的蒙版羽化（未完成）
- 现状：选区路径的蒙版是硬边（`dsh-editor-bridge.js` 里 `fillRect` 纯白）。
- 要做：导出前对外缘做渐隐（复用已有 `blurAlpha`），让模型把主体画在选区内、接缝消失。
- 验收：导出的蒙版 PNG 在边缘 alpha 呈梯度；单测覆盖梯度宽度。

### P1-2 重绘上下文裁剪 + 尺寸回执（未完成）
- 现状：整图送后端，尺寸不可控也不告诉用户。
- 要做：`command` 后端支持 `crop.context`（按选区较长边外扩，默认 25%），回执写 `720×760 → 992×1040`。
- 验收：单测断言裁剪框计算；回执包含两组尺寸。

### P1-3 PSD 混合模式与图层蒙版（未完成）
- 现状：一律按 source-over 合成；图层蒙版/剪贴蒙版未处理。
- 要做：支持 multiply/screen/overlay 等常用模式；应用 alpha 通道 -2 作为图层蒙版。
- 验收：自造 PSD 与手算结果一致；不支持的仍**明确登记**而不是静默糊掉。

### P2 批量可用性（未完成）
- 每份可配文案与槽位（API 已支持 `texts`，界面未暴露）。
- 批量结束产出清单（JSON：文件名 ↔ 素材引用）。

### P3 阻塞项：真实重绘后端
- 现状：本机无重绘模型（ComfyUI 端口未监听、无本地脚本）。
- 需要你决定：**本地脚本**（配 `kind: command`）还是 **ComfyUI**（配 workflow + `editImageNode`/`editMaskNode`）。
- 在此之前不会声称「局部重绘已跑通」。

## 纪律

- 每版：全量测试 → 构建 → `pack-image` → 部署 profile → 提交 → tag → Release。
- 每条能力：先定义可失败的验收，再实现；没跑过的不写成已跑通。
- 中文源码只用文件工具改，不用 PowerShell 批量替换（见 ADR 记录）。
