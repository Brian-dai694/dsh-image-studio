## Amazon 套图规范基准

规范来源和逐项验收见 [`amazon-image-suite-standard.md`](./amazon-image-suite-standard.md)。将 dLazy Amazon Product Image Suite 1.3.3 的**工作流/验收条款**作为本项目 Amazon 套图规范，不把其 CLI/云服务安装说明当成项目实现。

| 工作流条款 | 本项目状态 | 当前缺口/约束 |
|---|---|---|
| Listing 槽位 | 按 MAIN+PT01–PT06 默认 7 张 | 尚无 Amazon 专属槽位清单/状态台账 |
| A+ 类型与槽位 | Regular/Standard/Premium 分型与精确槽位已定义 | 尚无 A+ 专用版式生成器 |
| Product Reference Lock | 规范要求锁定产品身份/外形/材料/配件 | 还没有证据账本和跨槽 prompt 注入 |
| 尺寸 QA 与 canonical 输出 | 精确比例、实测像素、master/upload 与每槽唯一交付规则已定义 | 尚无自动读尺寸、等比处理与 manifest |
| 逐张确认与数据外传 | 每槽确认；云端上传前需用户确认 | 尚无 Amazon 专用套图状态机 |

**版本字段冲突说明：**ZIP 文件名/_meta.json 标 1.3.3，但 `SKILL-cn.md` 与 `SKILL.md` 的 frontmatter 标 1.2.1，正文 CLI 安装字段又有 1.2.0/1.0.9 冲突。基准身份以归档 `_meta.json` 的 1.3.3 记录，具体要求仅采纳正文中可明确核对的工作流条款。

## 两条能力线（先分清归属）

两条线共用**同一条命令通道**（白名单 + `expectedRevision` + 幂等 `commandId` + 审批），区别只在"谁在发起、谁在确认"。

| | 助手能力（面板对话框） | 插件能力（DSH ↔ 插件） |
|---|---|---|
| 使用者 | 坐在编辑器前的人 | DSH agent / 自动化 |
| 入口 | `host.js` 的 13 条正则指令 + 模型 op | 8 个 `media_image_*` 工具 + HTTP 路由 |
| 确认方式 | 弹框（人看得到画布） | 工具回执 + 高危审批 |
| 强项 | 自然语言、所见即所得、可随时接手 | 可编排、可批量、可无人值守 |
| 现状短板 | 只会固定说法、不知道自己做得对不对 | 无法自查、确认卡片读不懂、素材不持久 |

## 优化计划

排序原则：**先让两边都能"看见结果"，再补高频入口，最后才是画质。**

### 0.25.0 — 自检（两条线共用同一份测量）

**插件侧 B1 · `analyze`**
- `editor.analyze` 在**降采样**合成图上算：平均亮度、直方图粗桶、暗部/亮部裁切比例、R/G/B 偏色、清晰度（Laplacian 方差）、图层越界/零尺寸、文字层估计宽度超画布
- 工具 `media_image_analyze` 回测量 + `findings[]`，每条带 `suggestedCommand`（必须在白名单内，测试逐条核对）
- 只测量不给主观评价；测不出回 `needs_data`

**助手侧 A2 · 结果自检**
- `plan` / 套版 / 局部重绘执行完成后自动跑一次 `analyze`，回一句人话：`平均亮度 0.46 · 无裁切 · 文字未超框`；超阈值才提示（如"高光裁切 4.2%，要不要降一档亮度？"）
- 验收：全黑/过曝/偏蓝三张自造图方向正确；助手消息里出现数值而不是"看起来不错"

**插件侧 B3 · 确认卡片可核对**
- 确认框把 `{"layerId":"3"}` 解析成 `商品图 · image · 120,80 320×240`；不存在显示 `(图层已不存在)`
- 套版/重绘/批量统一走同一个渲染函数

### 0.26.0 — 高频入口与体验

**助手侧 A1 · 意图路由表**
- 把 13 条正则改造成声明式表：`{intent, patterns[], handler, needs}`，支持同义词（"把背景去掉/去掉背景/抠一下" → 抠图）
- 未命中时不再只说"还没听懂"，给出 3 条可点建议（来自可用指令表）

**助手侧 A3 · 高频操作**
- `撤销` `重做` `删除这层`（确认）`透明度 60%` `导出PNG`
- 全部走既有命令通道，不新增旁路

**插件侧 B4 · 重绘输入质量**
- 送后端的蒙版按选区较长边 1/8 渐隐（复用 `blurAlpha`）
- `command` 后端支持 `crop.context`（默认 25%），回执写 `720×760 → 992×1040`

**插件侧 B2 · 预览**
- `editor.preview_png {maxWidth}` → 降采样 PNG data URL（≤256 KB），`analyze` 可一并回
- 诚实边界：能否"看见"取决于宿主是否渲染 tool 结果里的图；不渲染时它只是可保存的缩略图

### 0.27.0 — 保真与运维

- **插件 B5**：PSD 常用混合模式（multiply/screen/overlay）+ 图层蒙版（alpha 通道 -2）；不支持项明确登记
- **插件 B6**：`POST /inpaint/{id}/cancel`，取消后不改画布
- **插件 B7**：素材/工程落盘（`config.dataDir` 已声明但未使用），重启后素材不丢
- **助手 A4/A5**：plan 执行前给缩略预览 + 步骤清单；失败给可点的"重试/改参数"建议

### P3 阻塞：真实重绘后端

本机无模型（ComfyUI 端口未监听、无本地脚本）。需要你定：**本地脚本**（`kind: command`）还是 **ComfyUI** workflows。
在此之前不声称「局部重绘已跑通」。

## 纪律

- 每版：全量测试 → 构建 → `pack-image` → 部署 profile → 提交 → tag → Release
- 每条能力：先定义可失败的验收，再实现；没跑过的不写成已跑通
- 中文源码只用文件工具改（见 ADR 记录）
