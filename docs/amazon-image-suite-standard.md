## 2. 套图范围

开始前确认交付类型、数量、画布比例/尺寸、站点、用途和必要的产品依据：

| 路径 | 规范范围 | 备注 |
|---|---|---|
| 完整 PDP 套图 | Listing `MAIN` + `PT01–PT06`（默认 7 张）+ 用户选择的 A+ 模块 | 按槽位逐项计数；不把不同 A+ 类型混成固定模块数 |
| 主图 + 副图 | `MAIN` + `PT01–PT06` | 默认 7 张；需要更多时用 `PT07–PT12` |
| 仅 A+ | Regular / Standard / Premium A+ | 未指定类型时先询问 |

### Listing 槽位

| Slot | 用途 | 比例/建议生成尺寸 |
|---|---|---|
| `MAIN` | 白底商品识别图 | 1:1，2048×2048 |
| `PT01` | 最强卖点或主场景 | 1:1 |
| `PT02` | 材质/结构细节证据 | 1:1 |
| `PT03` | 尺寸、适配或比例 | 1:1；专图只讲尺寸/规格 |
| `PT04` | 包装/实际包含物 | 1:1 |
| `PT05` | 使用/安装/护理步骤 | 1:1 |
| `PT06` | 无字生活方式场景或次要卖点 | 1:1 |

根据产品事实选副图任务，不为了凑齐类型而生成不相关图片。需要扩展时继续用 `PT07`–`PT12` 编号。

### A+ 类型与尺寸

| 类型 | 模块槽位 | 上传尺寸 | 建议 master |
|---|---|---:|---:|
| Regular A+ (`standard-large`) | `A+L01`–`A+L05` 单图模块 | 970×600 | 1940×1200 |
| Standard A+ (`standard`) | `A+S01` 横幅 | 970×300 | 同比例高分辨率 |
| Standard A+ (`standard`) | `A+S02`–`A+S04` 单图 | 970×600 | 1940×1200 |
| Standard A+ (`standard`) | `A+S05`–`A+S08` Highlight Tile | 220×220 | 同比例高分辨率；细文案优先放模块外文字字段 |
| Premium A+ (`premium`) | `A+P01-D`–`A+P06-D` 桌面 | 1464×600 | 2928×1200 |
| Premium A+ (`premium`) | `A+P01-M`–`A+P06-M` 移动配对图 | 600×450 | 1200×900 |

Premium 每个桌面/移动槽表达同一卖点，但要**独立构图**；不得把桌面横幅自动裁成移动图。`A+P07` 仅在用户明确要第七个 Premium 模块时采用。

可另按选定 A+ 类型搭叙事：品牌 Hero、痛点/场景、卖点/功能矩阵、技术/材料、证据、使用方法、变体、品牌背书。模块数量与实际 A+ 槽位表一致，不再采用不分类型的泛化“8 个 A+ 模块”。

## 3. 必须按顺序过的关口

### Gate 0：需求和证据

- 获取产品实物照片/准确描述、材质/颜色/结构/包装内容、目标人群、站点、核心卖点及可引用证据。
- 缺失的产品事实标为 `unknown`，不得用生成模型补造规格、配件、认证或性能数据。
- 明确 Listing 槽位与 A+ 类型/槽位；Listing 默认 `MAIN + PT01–PT06` 共 7 张，完整数量按用户确认的 Listing 槽位与 A+ 模块逐项相加。
- 对每张参考图分类：自有商品、包装/配件、自有生活场景、竞品、纯风格图。角色不清时询问。

### Gate 0.5：Product Reference Lock

生成前写产品参考锁：产品身份/变体、轮廓比例、颜色/表面、材料/结构、Logo/印字位置、套装数量/配件、包装事实、不可改变项。

- 图片只作其所属角色的证据；自有产品参考图是产品外观权威。
- 竞品参考只用于市场问题/布局类型，不能复制竞品设计、品牌、包装、精确构图或声明。
- 风格参考只约束用户明确要求的风格，不得覆盖商品事实。
- 有自有商品参考时，把锁加入每张 prompt 与 negative prompt；漂移时明确指出差异后再修正。

### Gate 1：主图基准先行

先做主图并审核，锁定产品外观、材质、颜色、比例和视觉基准后，才开始副图与 A+。

主图规范检查：

- 纯白背景目标 RGB(255,255,255)，成品像素复核背景；
- 商品主体占画面至少 85%，居中、完整、受光均匀；
- 不放文字、Logo、水印、装饰图形或误导性配件；服装不用人体模特；
- 不凭“模型说符合”验收，必须对最终导出文件检查尺寸、背景与内容。

这是参考 Skill 的项目基线，不替代 Amazon 当前站点政策审查。平台政策或类目例外不确定时先标记待人工核实，不声称合规保证。

### Gate 2：副图逐张规划、生成、检查

按转化信息覆盖挑选副图类型，不要求每种都做：信息图、不同角度、材质细节、生活场景、变体、包装清单、尺寸参照。

- 信息图：建议 4–6 个有证据的卖点，标注线确实指向对应结构；不得编造数字/认证/效果。
- 多角度/生活场景：优先让实际商品事实可核对；不能确认的外观细节要回问用户。
- 尺寸参照：只用已知尺寸和真实比例；禁止用误导物件或夸张比例。
- 每张生成后单独审核；反馈后只重做指定项。

### Gate 3：A+ 类型化规划

按第 2 节所选 Regular/Standard/Premium 类型与槽位表规划模块。A+ 应建立产品/品牌故事，不是重复 Listing gallery；素材比例、模块数量和 Premium 桌面/移动配对遵从对应规格。

- A+ 文案、数据、认证须有用户提供或已核实来源；没有证据不出现。
- 关键内容保持在画面安全区域；外缘 5% 是参考建议，不宣称为所有模块的平台硬性规则。文案大小在最终实际显示尺寸下检查，30pt 不视为跨模块通用值。
- 区分图片内文字与单独上传的 `textTitle/textBody`；若使用外部文字，避免图片内重复堆字。
- 延续已批准 MAIN 的产品事实、材质/颜色和 Reference Lock。


## 4. 人机确认与生成节奏

本项目沿用“每张先计划、再生成、再审核”的节奏：

1. 先收集缺少的产品事实与交付数量，不提前设计/生成。
2. 输出套图清单与**第一张**的构图/文案/提示词草案，询问用户是否确认开始第一张。
3. 只有明确确认后才触发一次生成；一次只运行一个生成请求，不批量并发生成整套。
4. 给出结果预览/文件与检查结论，问用户是否满意、是否继续下一张。
5. 用户反馈后只改被指出的部分；保留原结果，除非用户明确要求覆盖。
6. 每张记录状态：`planned → awaiting_approval → generating → review → approved/revise`；不把 `pending` 作业说成成品。

每个生成步骤应先展示：对应清单项、会修改的区域/蒙版预览（可用时）、输入素材与数据去向、生成后文件类型。任何高影响的覆盖/发布操作单独确认。

## 5. 一致性与最终验收

- 主图先锁定；副图和 A+ 以已批准主图/产品照片为视觉依据，不重新发明产品外观。
- 每张检查产品颜色/结构/材质、字体层级、色板与图标风格一致；尺寸和上传件必须按第 9 节的精确槽位验证。
- 对每个 Listing/A+ 槽位记录文件名、实际尺寸/比例、状态、产品证据与审核结果；交付完成/未完成清单。
- 正式交付目录每槽默认只留 canonical 成品；master 与 upload 都是交付要求时保留各一个，不放 rejected/raw/临时裁切文件。
- 有未审核、生成失败、产品事实未核实或政策待核验项，明确标待处理，不宣称整套通过。

## 7. 当前项目能力与未实现差距

- 已具备：受控图层编辑/活蒙版、PSD 套版、预览 overlay、自检、素材持久化、recipe、导出。
- 本地扩散 provider 只做填洞/小瑕疵，不是生成新主体；云端 provider 要先过数据上传/费用确认。
- 未实现：Amazon 套图向导/状态台账、产品事实证据账本、A+ 专用版式、安全区/主图 checker、精确比例 master→upload 处理及校验、canonical manifest。
- 规范文件不是生成模型、搜索引擎或合规认证器；不得从文档推断这些功能已上线。

## 8. 核验与冲突裁决

- 基准组合：amazon-image-planner 的**槽位、尺寸、Reference Lock、文件 QA** + dLazy 的**逐张确认、私有素材外传前确认**。
- Listing 默认 `MAIN + PT01–PT06` 共 7 槽，可按请求扩到 PT12；A+ 按 Regular/Standard/Premium 精确槽位计数，完整交付数量按用户批准的槽位清单汇总。
- 商业套图逐张计划、确认、生成、审核；有底层 batch API 不等于用户授权静默批量生成。
- 推荐 master 分辨率只是模型目标，upload 槽位尺寸才是交付目标；必须从文件读取实际像素并验证精确比例。比例不符是 intermediate，不是 approved master。
- Amazon 站点/类目规范可能变化；参考材料是规划基线，不是实时官方政策源。发布前仍需按目标站点人工核验。
